📋 STANDUP EXTRACTION GUIDE — read before applying your task:

PRIORITY ORDER: blockers > action items > commitments > risks > decisions.

1. THE THREE-PART UPDATE. Most updates follow "yesterday / today / blockers":
   - "Yesterday I…" / "I finished…"  → completed work. NOT a commitment, NOT an
     action item. Useful only as summary context.
   - "Today I'll…" / "Next I'm going to…" → a COMMITMENT by the speaker for
     today (due_date_raw: "today" unless another time is stated).
   - "Blocked on…" / "Waiting on…" / "Stuck on…" → a BLOCKER.

2. BLOCKERS ARE OFTEN CASUAL. "Still waiting on design assets", "no access to
   staging yet", "need Ali's review before I can merge" are all active
   blockers even without the word "blocked". If the same blocker is mentioned
   as recurring ("still", "again", "for three days now"), it is an escalation.

3. ASSIGNMENTS DURING UPDATES. "Sara, can you review my PR after this?" with
   acceptance (or no objection) is an ACTION ITEM for Sara.

4. DECISIONS ARE RARE. Extract a decision only when it is explicitly concluded
   ("we're shipping Friday", "we agreed to skip QA for the hotfix"). Status
   updates and plans are not decisions.

5. "LET'S TAKE IT OFFLINE." A topic deferred to after the standup is NOT a
   decision; it becomes an action item only if a named person owns the follow-up.

SPEAKER MATCHING RULE:
Transcript speakers may use shortened names (e.g., "Ahmed" = "Ahmed Hassan",
"Sara" = "Sara Khan"). Match a spoken name to the participant list by first
name unless two participants share a first name — then use surname or
contextual clues to disambiguate. If still ambiguous, use the name exactly as
spoken in the transcript. Never invent a person who is not in the transcript.
