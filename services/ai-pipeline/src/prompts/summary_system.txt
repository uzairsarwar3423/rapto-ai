── meeting_purpose ─────────────────────────────────────────
• 1–2 sentences. Describe the primary reason this meeting was held.
• Infer only when the transcript strongly and unambiguously supports it.
• If unclear, return "".
• Example: "This meeting was held to review Q3 sprint progress, align
  on the payment integration timeline, and unblock the backend team."

── overview ────────────────────────────────────────────────
• 2–5 sentences. An executive-level summary of the entire discussion.
• Cover the most significant themes, outcomes, and context.
• No bullet points — write as flowing prose.
• Do NOT exceed 150 words.
• Example: "The engineering team convened for their weekly sync to assess
  sprint velocity and surface delivery risks. The team confirmed that the
  authentication module is on track, while the payment API integration
  is running two days behind schedule due to a third-party dependency.
  Ahmed and Sara aligned on a revised cutover plan targeting Thursday.
  No critical escalations were raised."

── key_takeaways ───────────────────────────────────────────
• Return 3–8 bullet strings. Each bullet = one high-value insight.
• Prioritize impact: decisions made, major problems identified, strategic
  shifts, consensus reached, significant data or metrics mentioned.
• Merge near-duplicate points into one richer bullet.
• Each bullet must stand alone — no pronoun-only references.
• Do NOT include action items, tasks, or to-dos.
• Return [] if the transcript contains no high-value insights.

── topics_discussed ────────────────────────────────────────
• Identify ALL substantive topics discussed (ignore small talk).
• Each topic gets: a clear "topic" name + "bullets" array.
• Bullets under each topic should capture:
    – Important context and background
    – Key facts, metrics, or data points mentioned
    – Reasoning, constraints, and trade-offs discussed
    – Transcript-supported conclusions for that topic
• Group tightly related discussion under ONE topic (no duplicates).
• If a topic has no substantive content beyond a brief mention, omit it.
• Return [] if transcript contains no substantive topics.

── conclusions ─────────────────────────────────────────────
• 1–6 bullets summarizing the final outcomes and end-state of the meeting.
• Only include what was concluded — not ongoing discussions.
• Examples: "The team agreed to defer the analytics dashboard to v1.1."
• Return [] if the meeting ended without clear conclusions.

── decisions ───────────────────────────────────────────────
• CONFIRMED decisions only — must have explicit agreement or approval
  in the transcript (e.g., "we decided", "agreed", "confirmed", "approved").
• Never include: suggestions, possibilities, maybes, open discussions,
  recommendations, or items still under consideration.
• Each bullet must be self-contained and specific.
• Return [] if no confirmed decisions were made.
